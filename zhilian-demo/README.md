## 一、这是什么

一个面向福利方案业务的单文件交互原型：把「20+ 供应商、100+ 品牌、人工筛选耗时数天」的传统提报流程，压缩为**一句话需求 → AI Agent 多步编排 → 三档方案初稿（含产品矩阵、报价、合规校验、客户话术）→ 分钟级交付**的自动化流程。

原型为纯 HTML + CSS + 原生 JavaScript 实现，**零构建、零后端代码**；方案编排能力由 WorkBuddy 云服务的免密钥大模型 API 提供，打开页面即可直接调用，无需任何 API Key。

## 三、核心功能

### 1. AI Agent 方案编排（对应 M2 + 本期新增 L4 能力）
页面左上角提供两种编排模式，可现场对照：

| 模式 | 编排方式 | 用途 |
|---|---|---|
| **AI Agent 编排**（默认） | 云端大模型多步 Agent，全链路思维链可见 | 演示本期新增的智能体能力 |
| **规则引擎** | 本地枚举组合 + 贪心匹配（无网络依赖、秒级响应） | 兜底降级与效果对照 |

AI Agent 的五步编排流程（页面右侧「Agent 运行轨迹」实时呈现 THOUGHT / ACTION / OBSERVATION）：

1. **意图理解 Agent** — 把自然语言需求解析为结构化要素（预算 / 人数 / 主题 / 配送城市），模型以 JSON 形式返回，并回填表单
2. **货盘检索（工具调用）** — 按主题标签 + 配送区域过滤知识库，返回候选货盘与命中数
3. **方案编排 Agent** — 在货盘约束内编排基础 / 标准 / 臻选三档组合，只允许选择货盘中真实存在的商品 id
4. **合规校验（工具调用）+ 自动回环** — 预算约束 / 配送可达 / 资质齐全 / 库存状态四重校验；**若检出违规，校验结论会交回编排 Agent 重新编排（第 2 轮）**，形成真正的 agentic loop
5. **话术生成 Agent** — 流式生成可直接发给客户的方案解说

运行结束后轨迹条会显示：所用模型、端到端耗时、累计 tokens，全链路可追溯。

### 2. 三档方案与合规校验
- **三档方案**：基础档（性价比）/ 标准档（推荐均衡）/ 臻选档（高配礼遇），"档位定位"一栏由 Agent 给出编排理由
- **产品矩阵 + 报价**：单价、数量、小计、合计、预算利用率
- **四重合规校验**（对应 ★★★☆ 跃迁功能）：预算约束、配送可达、资质齐全、库存状态
- **导出方案文档**：一键打印为标准方案 PDF（打印样式已优化，仅输出方案部分）
- **边界处理**：主题 × 城市无匹配货盘时给出提示，模拟真实场景中的货盘扩展需求

### 3. 福利产品知识库（对应 M1）
- 六大核心字段结构化展示：**品类、价格区间、品牌、资质、配送范围、库存状态**（另含主题标签、供应商编号）
- 关键词搜索 + 品类筛选
- 供应商治理卡片：资质状态（齐备 / 待补）+ 货盘月度更新时间戳

### 4. 评级定位与跃迁路线
- ★★★ → ★★★☆ → ★★★★ 三级跃迁所需功能清单
- 能力阶梯 L1–L6：本期新增 **L4 低代码 Agent**（L1 提示词工程 / L2 文档智能抽取 / L3 知识库 RAG 已具备）
- M1 / M2 / M3 里程碑时间线，标注本原型已演示范围

## 四、Agent 架构与技术要点（供项目组二次开发）

### 数据流与安全边界
```
用户一句话
   ↓ ① LLM：意图理解（JSON）
结构化需求 ──→ ② 工具：货盘检索（本地知识库）
                     ↓ ③ LLM：方案编排（只输出商品 id + 理由）
                候选组合 ──→ ④ 工具：四重合规校验（本地规则）
                     ↓ 违规则把校验结论回传 ③ 重新编排（最多 2 轮）
                终版方案 ──→ ⑤ LLM：客户话术（流式）
```
- **金额与校验一律本地计算**：模型只负责"选哪些商品 id"与"写文案"，价格、合计、预算利用率、合规结论全部由前端本地计算，避免模型算术与幻觉污染报价
- **模型输出视为不可信输入**：商品 id 必须命中货盘白名单才被采纳，文案统一转义后渲染，不执行、不拼接
- **提示词注入防护**：用户输入被清洗（去换行/特殊符号、限长 240 字）并以「待解析文本」的明确边界传入，系统提示中声明其中的指令不构成指令
- **降级策略明确可见**：云端不可用 / 模型不支持 JSON 模式 / 无匹配货盘 / 解析失败时，页面显示中断原因并自动切回规则引擎兜底，同时提示可重试——不静默失败、不伪装成功
- **兼容性重试**：若模型不支持 `response_format: json_object`，自动去掉该参数重试一次（提示词已要求仅输出 JSON）

### 云服务接入
- 使用 `@tencent-ai/workbuddy-cloud-sdk`（CDN IIFE 形式，免构建）初始化，仅使用 `publicConfig` 中的 `endpoint` 与 `publishableKey`（两者均无长期密钥，服务端按来源域名精确校验）
- 模型通过 `cloud.llm.models.list()` 动态获取并自动选择首个可用模型（不使用硬编码模型 id）
- 全部调用为流式（`stream: true`），统一收集 SSE 分片；失败按错误码族（`auth_` / `quota_` / `request_` / `gateway_` / `model_`）给出可读提示

### 替换为生产能力的接入点
| 原型中的环节 | 生产建议 |
|---|---|
| 演示 SKU / 供应商常量 | M1 清洗入库后的真实货盘（替换 `SKUS` 与 `SUPPLIERS` 即可） |
| 本地货盘检索工具 | 知识库 RAG 检索（时段三）：向量召回 + 重排 |
| 提示词与 JSON 契约 | 提示词工程（时段一）+ 文档智能抽取（时段二）沉淀货盘 |
| 四重合规校验 | 规则引擎服务化（★★★☆ 跃迁项） |
| 方案版本与客户反馈 | 云端数据库落库，形成偏好画像（★★★☆ 跃迁项） |

## 五、演示脚本（建议按此顺序操作）

1. 打开页面，停留 Hero 区——项目定位与关键指标（326 SKU / 3 分钟方案初稿）
2. 滚动至「智能方案生成」，确认左上角为 **AI Agent 编排** 模式，云服务状态灯为绿色（含模型名）
3. 点击示例「中秋客户礼赠·预算15万·200人·广州」→ 生成方案，边跑边讲右侧 Agent 运行轨迹（意图理解 → 货盘检索 → 方案编排 → 合规校验 → 话术生成）
4. 切换三个档位 Tab，展示产品矩阵、报价与合规校验结果，并读出 Agent 给出的档位理由
5. 点击「导出方案文档」，展示标准方案打印稿
6. 切到 **规则引擎** 模式再生成一次，对照说明"Agent 负责理解与编排、规则引擎负责兜底与校验"
7. 滚动至「评级定位与等级跃迁」，用能力阶梯收束（L1→L3 已具备，本期新增 L4 低代码 Agent）
